# Quickstart: 먼저 말 거는 나비스 — 약속 검증 가이드

수동 시나리오는 사람이 판정한다(헌장 품질 게이트 — 모델 판단이 섞인 기준은 CI 에 넣지 않는다).
결정적인 것(일정 검증 · 다음 회차 · 선점 · 계약)은 `pnpm test` 가 덮는다.

## 준비

### 로컬

1. `pnpm db:migrate`. 0011(messages 표 · promises · promise_runs · conversations 열)이 적용된다.
2. `apps/server/.env` 에 `NAVIS_TICK_TOKEN=<API_TOKEN · MCP 토큰과 다른 값>` 을 둔다.
3. 로컬에는 Scheduler 가 없다. 다른 터미널에서 1분마다 직접 부른다.
   ```sh
   while true; do curl -s -X POST localhost:3000/api/internal/tick \
     -H "Authorization: Bearer $NAVIS_TICK_TOKEN"; echo; sleep 60; done
   ```

### 운영 (순서가 중요하다)

1. Secret Manager 에 `navis-tick-token` 을 만들고 `deploy/service.yaml` 의 **server 컨테이너에만** 주입한다.
2. 운영 DB 에 0011 을 적용한다. 배포와 분리된 수동 단계다.
3. main 에 push 해 배포한다.
4. Cloud Scheduler API 를 켜고 작업을 만든다. `deploy/README.md` 에 명령을 적는다.
   - 일정 `* * * * *` (비용이 걱정되면 `*/5 * * * *`)
   - 대상 `POST https://<서비스 주소>/api/internal/tick`, 헤더 `Authorization: Bearer <토큰>`
   - `attemptDeadline 1800s`, `maxRetryCount 0`
5. S0 확인 뒤 0012(`conversations.messages` 제거)를 적용한다.

## 시나리오

| # | 확인 | 방법 | 기대 |
|---|---|---|---|
| S0 | 메시지 이전(R7) | 0011 전후로 방별 메시지 수와 마지막 메시지를 대조한다 | 전부 같다. 순서도 같다 |
| S1 | 한 번짜리 약속(US1) | "2분 뒤에 물 마셨는지 물어봐줘" → 창을 닫는다 | 확인 문장에 실제 시각이 있다. 3분 안에 알림이 오고, 누르면 "나비스" 방에 사용자 말풍선 없이 "⏰ 약속: …" 메시지가 있다. 답하면 맥락이 이어진다. 약속은 끝남으로 표시된다 |
| S2 | 침묵(US2, SC-002) | "매시 정각에 지금 시각 보고 짝수 시면 알려줘" 를 몇 시간 둔다 | 홀수 시: 메시지 · 알림 없음, 실행 기록 `silent`. 짝수 시: `spoke` |
| S3 | 반복하지 않기 | "매시간 비트코인 가격 보고 1억 넘으면 알려줘(넘은 상태가 이어지면 다시 말하지 마)" | 첫 도달 때만 말하고, 메모에 그 사실이 남는다 |
| S4 | 최소 간격 · 상한(FR-005 · 006) | "1분마다 알려줘" / 약속 21개 | 1시간으로 맞췄다고 말한다 / 21번째는 상한 안내 |
| S5 | 제안(US3, SC-008) | 날짜가 걸린 계획 10개, 그리고 인사 5개를 말한다 | 동의 없이 생긴 약속 0. 인사에는 제안 0. 거절한 제안을 다시 하지 않는다 |
| S6 | 관리(US4) | 화면에서 끄기 · 다시 켜기 · 지우기, 대화로 "유가 약속 꺼줘" | 꺼진 동안 실행 없음. 다시 켜면 놓친 회차를 몰아서 돌리지 않는다. 화면과 대화 목록이 같다 |
| S7 | 메인 방(US5) | 새 회원으로 로그인, 메인 방 지우기 시도 | 방이 이미 있고 맨 위에 고정. 지우기 409. `?c=` 없이 열면 메인 방 |
| S8 | 긴 방 성능(SC-004) | 메인 방에 메시지 500개를 넣고(스크립트) "안녕" 첫 응답 시간과 방 열기 시간을 잰다 | 새 방 대비 첫 응답 +20% 이내. 방 열기 1초 이내. 위로 올리면 50개씩 더 온다 |
| S9 | 동시 실행(SC-003, R4) | 약속 턴이 도는 동안(웹 조회가 있는 약속) 대화 "안녕"을 보낸다. 서버 메모리를 관찰한다 | 첫 응답 +20% 이내. server 메모리 1Gi 안. 넘으면 1.5Gi 로 올리고 기록한다 |
| S10 | 대화 양보(R4) | 긴 대화 턴 도중 약속 시각이 된다 | 약속은 대화 턴이 끝난 뒤 실행된다 |
| S11 | 중복 방지(SC-005) | 실행이 1분 넘게 걸리는 약속(웹 조회 여러 번) | 같은 회차 `promise_runs` 1행, 메시지 1개 |
| S12 | 중단 복구(R3) | 약속 실행 중 서버를 재시작한다 | 임대 만료 후 `running` 이 `failed(중단)` 으로 닫히고 다시 실행된다 |
| S13 | 실패 처리(R11) | Claude 토큰을 지운 채 반복 약속 3회 | 매회 `failed` + 이유. 3회째에 꺼지고 메인 방에 한 번 알린다 |
| S14 | 분리(SC-007) | 회원 A 의 약속 id 로 B 가 PATCH · DELETE, B 의 대화에서 `list` | 404. B 의 목록에 A 의 것 없음 |
| S15 | tick 자격(R10) | `/api/internal/tick` 을 토큰 없이, `API_TOKEN` 으로, MCP 토큰으로 부른다 | 전부 401. 토큰 미설정 서버는 404 |
| S16 | tick 비용(SC-006) | 할 일 없는 tick 의 응답 시간과 로그 | 1초 미만. 모델 · 임베딩 호출 없음 |
| S17 | 외부 MCP(FR-029) | Claude Code 에서 navis MCP 도구 목록을 본다 | `promise` 도구 없음 |
