# Quickstart: 주제 대화 검증

## 준비

```bash
docker compose up -d
pnpm db:migrate            # 0016_topic_rooms
pnpm dev
```

로그인한 회원에게 Claude 토큰이 등록되어 있어야 한다. 서로 다른 주제의 기억을 몇 개 남겨 둔다 — "나비스" 방에서:

- "이사: 망원동 집은 채광이 좋았고 합정 집은 역에서 가까웠어" (project 이사)
- "회사: 다음 분기 목표는 결제 전환율 올리기야" (project 회사)
- "나 땅콩 알레르기 있어" (개인)

## 자동 검사

```bash
pnpm typecheck && pnpm lint && pnpm test
pnpm --filter @navis/web build
```

domain: focus 적용 표 · `buildTurnTools` 의 "이 방의 주제" 절([contracts/memory-tools.md](./contracts/memory-tools.md)).
server: `POST /conversations` 200/201/400 · 목록의 `project` · `memoryCount` · 예전 방 숨김([contracts/http.md](./contracts/http.md)).

## 수동 시나리오

| # | 할 일 | 기대 |
|---|---|---|
| 1 | 위쪽 바 방 메뉴 → 새 주제 대화 → '이사' | "이사" 방이 열리고 칩 '📁 이사 · 기억 N개' (US1-1, US2-1) |
| 2 | "전에 본 집 중에 어디가 나았지? 그리고 다음 분기 목표도 같이 말해줘" | 집 얘기는 답하고, 분기 목표는 이 방 범위에 없다고 하거나 넓힐지 묻는다 (US1-3) |
| 3 | "전체에서 찾아줘" | 회사 기억까지 찾아 답한다. 다음 질문은 다시 이사 범위 (US1-5) |
| 4 | "잔금일은 12월 5일로 정했어" | 기억 화면에서 그 기억의 프로젝트가 '이사', 칩 숫자 +1 (US1-4, US2-3) |
| 5 | "나 다음 달 생일이야" | 기억이 개인(프로젝트 없음)으로 남는다 (research R4) |
| 6 | 방 메뉴 → 새 주제 대화 → '이사' 다시 | 새 방이 생기지 않고 기존 "이사" 방이 열린다 (US3-5) |
| 7 | 새 주제 '이사준비' 입력 | '이사'를 쓸지 먼저 묻는다 (US1-2) |
| 8 | 칩 누르기 | 이사 기억 목록(최근순) + 개인 기억도 쓰인다는 안내 (US2-2) |
| 9 | 이 방에서 "내일 9시에 잔금 서류 챙기라고 알려줘" | 약속이 생기고, 나비스 방으로 알린다고 확인. 때가 되면 메시지는 "나비스" 방 (FR-019, FR-020) |
| 10 | 방 메뉴 | "나비스" 맨 위, 주제 방은 최근 대화순 · 기억 개수 (US3-1) |
| 11 | 기억 화면에서 '이사' → '이사 2026' 이름 바꾸기 | 방 제목과 칩이 '이사 2026' 으로 (FR-004) |
| 12 | 칩 시트 → 이 방 지우기 | 확인 후 "나비스" 방이 열리고, 이사 기억은 기억 화면에 남아 있다 (US3-3) |
| 13 | 새로고침 | "나비스" 방이 열린다 (US3-6) |
| 14 | 주제 방에서 답을 받은 뒤 창을 닫아 두고 알림 누르기 | 그 주제 방이 열린다 (FR-021) |
| 15 | "나비스" 방에서 2번 질문 | 두 주제 모두에서 찾아 답한다 — 기존과 같다 (FR-009) |

SC-002 · SC-003 · SC-004 는 2–5번을 주제 둘로 10번씩 돌려 사람이 판정한다(헌장: 확률적 기준은 수동).
