# Feature Specification: 자유 주제 방 — 메인 방 + 회원이 주제를 쓰는 방, 답마다 참고한 기억 보이기

**Created**: 2026-11-13

**Status**: 구현됨(로컬 main, 운영 배포 전) — 커밋 e68c878 · b516358 이후

**Supersedes**: [specs/005-topic-rooms](../005-topic-rooms/spec.md)(보류)

## 배경

회원 요구(원문 요약): "주제마다 별도 대화를 만들고, 그 대화가 어떤 기억을 바탕으로 하는지 직관적으로 보이게."

005는 주제 방을 **기억의 프로젝트 하나**에 묶었다. 운영에서 프로젝트 표기가 흩어져 있어(한 회원 39개, 붙은 비율 70%)
표기가 다른 기억이 조용히 빠질 위험 때문에 2026-10-23 보류했다. 당시 대안: (1) 답마다 '참고한 기억' 표시를 먼저,
(2) 정말 필요해지면 기억을 좁히지 않는 그냥 새 방.

회원이 실제로 방 분리를 원했으므로(2026-11-13 사용자 확인) 대안 (2)를 기반으로, **주제를 회원이 글로 직접 쓰는** 방식으로 연다.

## 결정 (2026-11-13 사용자 합의)

1. **메인 방 하나**: '나비스' 방은 맨 위에 고정, 지울 수 없고 주제가 없다. 관리자의 전하기는 늘 메인 방으로 온다.
2. **주제 방 여러 개**: 회원이 주제를 자유롭게 쓴다('강의 준비', '안녕' 모두 가능, 최대 `TOPIC_MAX`자). 주제가 곧 방 이름이다.
3. **초점이지 격리가 아니다**: 주제는 시스템 프롬프트의 '이 방의 주제' 절로 들어간다. recall 검색어에 주제를 함께 담게 할 뿐,
   기억을 거르지 않는다. 개인 기억 · 다른 주제의 기억도 필요하면 쓴다. recall 은 의미 검색이라 프로젝트 표기와 무관하게 찾는다.
4. **저장**: 프로젝트는 지금처럼 내용으로 정하고, 방 주제는 **태그**로 붙인다(기억 MCP 가 강제로 붙인다 — 모델에 맡기지 않는다).
5. **약속은 만든 방으로 온다**(사용자 결정). 만든 방이 지워졌거나 없으면 메인 방. 약속 턴도 그 방의 최근 대화 · 주제로 실행한다.
   알림을 누르면 그 방이 열린다.
6. **참고한 기억은 필수**: 주제를 글로 쓰면 '기억 N개' 같은 묶음 수를 보일 수 없다. 대신 답마다 실제로 도구가 넘긴 기억
   (`memoriesUsed`)과 저장한 기억(`savedMemories`)을 보인다.

## 화면

- 데스크탑(lg+): 왼쪽 사이드바(새 주제 방 · 메인 방 · 주제 방 목록 · 기억 · 설정), 가운데 대화, 오른쪽 패널(xl+:
  이 답에 참고한 기억 · 방금 저장 · 이 방의 약속). 기억 · 설정 화면도 같은 틀(`AppFrame`).
- 모바일: 위쪽 왼쪽 메뉴 버튼으로 방 목록 서랍.
- 방 메뉴(⋯): 주제 고치기 · 방 지우기(확인 창, 대화는 되살릴 수 없음, 기억은 남음, 약속은 이후 메인 방으로).
- 위쪽 바: 주제 방이면 방 이름 + '주제' 칩(눌러 고치기). 데스크탑 메인 방은 제목을 두지 않는다.
- 보고 있지 않은 방에 새 메시지(약속 결과 등)가 오면 사이드바 점이 밝아진다(이 기기 localStorage 기준).

## 서버 · 데이터

- `conversations.topic text null` (마이그레이션 0016). 메인 방 · 예전 방은 null. 주제 없는 예전 방은 목록에 보이지 않는다.
- `POST /conversations {topic}` → 빈 방 생성 · `PATCH /conversations/:id {topic}` → 주제 · 이름 변경 + 세션 비움
  (옛 주제가 박힌 세션을 잇지 않게) · `GET /conversations/:id/promises` → 그 방으로 올 켜진 약속
  (메인 방은 만든 방이 없거나 지워진 약속 포함).
- 메시지 meta 에 `savedMemories`(저장한 기억 사본).
- 기능 안내서(`guide`)에 '주제 방' 항목 추가, '못 하는 것'에서 "방은 하나" 문장 제거. 회원에게 전하기는 언급하지 않는다(specs/004 FR-002).

## 범위 밖 / 나중

- 다른 기기 간 '읽음' 동기화(점은 기기별).
- 방 순서 바꾸기 · 고정, 방 검색.
- 주제로 기억을 실제로 좁히는 모드(005의 초점 범위) — 프로젝트 표기 정리 이후 다시 검토.

## 배포 순서
