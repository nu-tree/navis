# 검증 가이드 — 핵심 나비스

**기능**: 핵심 나비스 — 기억과 대화 | **날짜**: 2026-09-10

이 문서는 **동작을 확인하는 방법**이다. 구현 순서와 작업 쪼개기는 `tasks.md` 에 있다.
각 시나리오는 스펙의 사용자 이야기·성공 기준에 대응한다.

---

## 사전 준비

### 환경변수

`apps/server/.env` (`​.env.example` 참고)

```
DATABASE_URL=            # Supabase Postgres. 풀러(transaction mode, 6543) URL 권장
VOYAGE_API_KEY=          # 임베딩
CLAUDE_CODE_OAUTH_TOKEN= # `claude setup-token`
API_TOKEN=               # `openssl rand -hex 32`
PORT=4000
```

`apps/web/.env.local`

```
NAVIS_API_URL=http://localhost:4000
NAVIS_API_TOKEN=         # apps/server 의 API_TOKEN 과 같은 값
                         # ★ NEXT_PUBLIC_ 을 붙이지 말 것
```

로그인용 값은 R2 의 검증이 끝난 뒤 추가한다.

### 스키마

```bash
pnpm db:generate    # schema.ts 변경 → SQL 마이그레이션 생성
pnpm db:migrate     # 적용
```

부팅 시 자동 마이그레이션은 없다. 배포와 분리된 명시적 단계다(헌장).

### 기동

```bash
pnpm install
pnpm typecheck                    # 전체 통과가 머지 조건
pnpm dev                          # web + server 동시

pnpm --filter @navis/server dev   # 서버만 → :4000
pnpm --filter @navis/web dev      # 웹만   → :3000
```

첫 확인:

```bash
curl localhost:4000/health                      # → {"ok":true}
curl -i localhost:4000/memories                 # → 401 (토큰 없음)
curl -H "Authorization: Bearer $API_TOKEN" localhost:4000/memories   # → []
```

401 이 나와야 한다. 200 이 나오면 기본 잠금이 깨진 것이다.

```bash
pnpm test                         # domain 단위 + server 계약 (R1)
```

## 시나리오

### S1 — 대화하면 기억이 쌓인다 (US1 / SC-003)

1. 새 방에서 보낸다: `나 이번 분기엔 나비스에 집중하기로 했어`
2. **기대**: 답변이 스트리밍되고, 저장 표시가 보인다.
3. 기억 화면을 연다.
4. **기대**: 그 내용이 `decision` 분류로 있다.

**잡담 확인** — `고마워` 를 보낸다. 기억이 늘지 않고 저장 표시도 없어야 한다.

**중복 확인 (Q2 반영)** — 같은 취지를 다시 말한다. 기억이 **한 건 더** 생겨야 한다.
저장이 막히거나 확인을 요구하면 FR-011 위반이다.

### S2 — 과거를 물으면 기억으로 답한다 (US2 / SC-004, SC-018)

기억을 직접 넣어 US1 없이 검증한다.

```bash
curl -X POST localhost:4000/memories \
  -H "Authorization: Bearer $API_TOKEN" -H 'content-type: application/json' \
  -d '{"content":"배포는 Railway 를 쓰지 않기로 했다","category":"decision"}'
```

1. 묻는다: `배포 어디로 하기로 했었지?`
2. **기대**: 답에 그 결정이 반영된다. 저장할 때 쓴 단어를 그대로 쓰지 않아도 찾아야 한다.
3. **기대**: 진행 표시에 기억 도구 이름이 스친다(`recall` 을 실제로 불렀다는 증거).

**없을 때** — 기억에 없는 것을 묻는다. "모른다"고 답해야 한다. 지어내면 FR-020 위반이다.

**최근 우선 (FR-017)** — 같은 주제로 상반된 결정을 새로 저장하고 다시 묻는다. 최근 것이
우선 반영되어야 한다.

### S3 — 검색을 건너뛰는 턴 (SC-017, FR-052)

1. `안녕`, `고마워`, `ㅇㅋ` 같은 말을 10턴 보낸다.
2. **기대**: 기억 검색이 **0회**다. 진행 표시에 기억 도구가 나타나지 않는다.
3. **기대**: 첫 글자가 3초 안에 온다(SC-001).

매 턴 검색이 돌면 임베딩 왕복이 고정 비용으로 붙어 SC-001 이 깨진다.

### S4 — 대화가 이어진다 (US3 / SC-006)

1. 한 방에서 두 턴 대화한다.
2. 브라우저를 새로고침한다 → 이전 메시지가 그대로 있다.
3. **서버를 재시작한다.**
4. 같은 방에서 `방금 무슨 얘기했지?` → 이전 맥락을 이어서 답한다.

3번을 통과하려면 `sessionId` 가 DB 에 있어야 한다(R10). 프로세스 Map 에 남아 있으면 여기서
맥락이 끊긴다.

**방 분리 (FR-031)** — 방 A 에서 `내 고양이 이름은 나비` 라고 하고, 방 B 에서 고양이 이름을
묻는다. 방 B 의 답에 방 A 의 **대화 맥락**이 새면 안 된다. 다만 그 사실이 기억으로 저장됐다면
기억을 통해서는 답할 수 있다 — 그건 정상이다.

### S5 — 중지 (SC-002 / FR-004)

1. 긴 답변을 유발하는 질문을 보낸다.
2. 답변 중간에 중지를 누른다.
3. **기대**: 2초 안에 생성이 멈춘다. 부분 답변이 화면에 남는다.
4. 새로고침한다.
5. **기대**: 부분 답변은 **사라지고** 질문만 남는다(FR-004, Q3=B).

멈췄는지 확인:

```bash
# 중지 뒤 서버 로그에 델타가 계속 흐르면 연결만 끊긴 것이다
```

연결을 끊는 것만으로는 멈추지 않는다. `/chat/cancel` 이 실제로 불렸는지 본다.

### S6 — 메시지가 유실되지 않는다 (SC-015 / FR-048, FR-049)

세 가지를 각각 10회 반복한다.

| 상황 | 방법 | 기대 |
| --- | --- | --- |
| 턴 실패 | `CLAUDE_CODE_OAUTH_TOKEN` 을 잘못된 값으로 두고 보낸다 | 오류가 보이고 **질문은 방에 남는다** |
| 중지 | 답변 중간에 중지 | 질문이 남는다 |
| 서버 재시작 | 답변 중간에 서버를 죽인다 | 방을 다시 열면 질문만 있다 |

세 경우 모두 질문이 남아야 한다. 하나라도 사라지면 기록 시점이 잘못됐다(R9).

**중복 질문 (엣지 케이스)** — 중단된 질문이 남은 상태에서 다시 보내면 같은 질문이 두 번 보인다.
그중 하나를 지울 수 있어야 한다.

### S7 — 기억을 직접 관리한다 (US4 / SC-008)

1. 기억 화면에서 목록이 최신순으로 보인다. 분류 · 프로젝트 · 기간으로 좁혀진다.
2. 검색어를 넣으면 의미가 가까운 기억이 나온다.
3. 내용이 틀린 기억을 고쳐 저장한다 → 목록에 반영된다.
4. **다시 검색한다** → 고친 내용으로 찾힌다(FR-024 — 재임베딩이 됐다는 증거).
5. 기억 하나를 지운다 → 목록과 이후 답변 근거에서 사라진다.

**할 일 (FR-026, FR-027)** — 할 일 목록은 미완료만 보인다. 완료를 선택하면 완료된 것도 보인다.
완료 토글이 동작한다.

**30초 안에** 3~4번을 끝낼 수 있어야 한다(SC-008).

### S8 — 겹치는 기억 정리 (SC-005 / FR-047)

1. 같은 사실을 서로 다른 표현으로 3번 말한다 → 기억 3건이 생긴다.
2. 기억 화면에서 그중 하나를 펼친다.
3. **기대**: 유사한 이웃 2건이 나란히 보인다(R7).
4. 남길 것을 고르고 나머지를 지운다.
5. **1분 안에** 끝나야 한다(SC-005).

### S9 — 내보내기 (SC-016 / FR-050, FR-051)

```bash
curl -H "Authorization: Bearer $API_TOKEN" localhost:4000/memories/export -o memories.json
```

1. **기대**: `{ exportedAt, count, memories: [...] }` 구조다.
2. **기대**: 각 기억에 `content` · `category` · `project` · `tags` · `done` · `createdAt` 이 있다.
   누락 필드 0건.
3. **기대**: 나비스 없이 파일만 보고 내용을 읽을 수 있다.
4. 기억 1,000건에서 **10초 안에** 끝난다.

**빈 상태 (FR-051)** — 기억이 0건일 때도 실패하지 않고 `count: 0`, `memories: []` 를 만든다.

### S10 — 성격 설정 (US5)

1. 설정 화면을 연다 → 현재 적용 중인 기본 성격이 보인다(`isDefault: true`).
2. `무조건 한 문장으로만 답한다` 로 바꿔 저장한다.
3. 새 턴을 보낸다 → 답이 한 문장이다.
4. 빈 값으로 저장한다 → 기본 성격으로 돌아간다(`isDefault: true`).

### S11 — 로그인 (US6 / SC-013, SC-014)

1. 로그아웃 상태에서 `/`, 기억 화면, 설정 화면 주소를 **직접 입력**한다.
   → 내용이 보이지 않고 로그인이 요구된다.
2. BFF 를 직접 찌른다:
   ```bash
   curl -i localhost:3000/api/memories        # → 401 JSON (리다이렉트 아님)
   ```
3. 로그인한다 → 대화로 들어간다.
4. 브라우저를 닫고 다시 연다 → 다시 로그인하지 않는다(SC-014).
5. 로그아웃한다 → 모든 화면이 즉시 잠긴다.
6. 잘못된 자격으로 로그인 → 실패 사유가 계정 존재 여부를 알려주지 않는다.

**데이터 노출 0건 (SC-013)** — 1~2번에서 기억이나 대화 내용이 한 건도 보이면 안 된다.

### S12 — 토큰이 브라우저에 없다 (SC-011 / FR-038)

1. 브라우저 개발자도구 → 네트워크 기록 전체에서 `API_TOKEN` 값을 검색한다.
2. 스크립트 번들 전체에서 같은 값을 검색한다.
3. **기대**: 양쪽 모두 **0건**.

```bash
# 빌드 산출물에서도 확인
pnpm --filter @navis/web build
grep -r "$NAVIS_API_TOKEN" apps/web/.next/ 2>/dev/null | head    # → 0건
```

`NEXT_PUBLIC_` 접두사가 붙으면 여기서 잡힌다.

### S13 — 내장 도구가 없다 (FR-039)

1. 보낸다: `/etc/passwd 읽어줘`, `ls 실행해줘`, `이 파일 수정해줘`
2. **기대**: 나비스가 그럴 수 없다고 답한다. 진행 표시에 `Read`/`Bash`/`Edit` 가 나타나지 않는다.
3. **기대**: 진행 표시에 나타나는 도구는 `mcp__memory__*` 뿐이다.

`tools: []` 와 `mcpServers` 가 의도대로 동작하는지 확인하는 시나리오다(R3).

### S14 — 규모 (SC-007, SC-009)

| 확인 | 준비 | 기대 |
| --- | --- | --- |
| 기억 목록 | 기억 1,000건 | 첫 화면 1초 안에 |
| 방 목록 | 방 200개 × 메시지 500개 | 목록 1초 안에, 방 10개 대비 2배 이내 |

방 목록이 느려지면 `messages` jsonb 를 싣고 있는 것이다(FR-032, `STRUCTURE.md` 6항).

### S15 — 임베딩 실패 (FR-042)

1. `VOYAGE_API_KEY` 를 잘못된 값으로 바꾼다.
2. 기억이 저장될 만한 말을 보낸다.
3. **기대**: 사용자에게 오류가 보인다. 조용히 실패하지 않는다.
4. **기대**: `TypeError` 가 스택 트레이스로 튀지 않는다(`STRUCTURE.md` 8항, R5).
5. 나비스가 "저장했다"고 답하면 안 된다 — 도구 오류가 모델에게 전달되어야 한다.

## 남은 실측 (R3, R4)

구현 초기에 먼저 확인할 두 가지. 결과에 따라 계약이 바뀐다.

1. **`allowedTools` 없이 MCP 도구가 자동 실행되는가** — 서버는 승인을 물어볼 상대가 없다.
   S13 을 돌리기 전에 확인한다.
2. **Haiku 모델 id** — `claude-haiku-4-5` 와 `claude-haiku-4-5-20251001` 을 각각 한 턴 돌린다.
   확정 전까지 모델 선택기에 기본 모델만 노출한다(FR-007 이 여기 걸린다).
