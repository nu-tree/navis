# 계약 — 대화 스트림 (SSE)

`POST /chat` 과 `POST /api/chat` 이 나르는 유일한 계약. `ChatEvent` **판별 유니온**이라
클라이언트가 문자열을 손으로 분기하지 않고 타입으로 받는다.

전송 형태: 각 이벤트를 `JSON.stringify` 해 SSE `data:` 한 줄로 보낸다.

## 이벤트

| `type` | 실린 것 | 화면이 하는 일 | 요구 |
| --- | --- | --- | --- |
| `delta` | `text` | 스트리밍 버퍼에 이어 붙인다 | FR-002 |
| `thinking` | `text` | **지금은 쓰지 않는다** — 계약에만 둔다 | — |
| `status` | `tool` | 진행 표시에 도구 이름을 보여준다 | FR-003 |
| `tool` | `label` | 완료된 도구 한 줄 | FR-003 |
| `done` | `message`, `sessionId`, `saved` | 확정 메시지를 목록으로 옮긴다 | FR-002, FR-010 |
| `aborted` | `reason` | 부분 답변을 화면에 남긴다 | FR-004 |
| `error` | `message` | 읽을 수 있는 오류를 보여준다 | FR-040 |

## 규약

**`done.message` 가 권위다.** 델타를 이어 붙인 문자열과 다를 수 있다 — 최종 전문은 서버가
정한다. 화면은 `done` 이 오면 자기 버퍼를 버리고 `message` 를 쓴다.

**`done.saved`** 는 이 턴에 기억 도구를 실제로 불렀는지다(FR-010). 화면의 저장 표시 조건이
이 하나뿐이므로, MCP 도구 호출을 세어 채운다. 판단만 하고 부르지 않은 턴은 `false` 다.

**`done.sessionId`** 는 `conversations.sessionId` 에 저장한다(R10). 새 세션이면 이 시점에
처음 알게 된다.

**프레임 직렬화.** 여러 콜백에서 `await` 없이 쓰면 프레임이 섞인다. 프라미스 체인으로
직렬화한다(현재 `routes/chat.ts` 가 이미 그렇게 한다).

**빈 문자열과 `null` 의 구분.** 스트리밍 버퍼가 `""` 이면 "턴은 시작됐지만 첫 토큰 전"이고,
`null` 이면 "진행 중인 턴이 없다"다. 이 구분이 FR-003 의 진행 표시 조건이다.

**중지 뒤 늦은 델타.** 턴마다 로컬 버퍼를 따로 둔다 — 공용 상태에 이어 붙이면 중지 후 도착한
조각이 다음 턴에 섞인다.

## 순서 보장

```
(사용자 메시지는 이미 커밋됨 — R9)
status? → delta* → done          정상
status? → delta* → aborted       중지
status? → delta* → error         실패
```

`done` · `aborted` · `error` 중 **정확히 하나**가 마지막에 온다. 그 뒤 스트림이 닫힌다.
